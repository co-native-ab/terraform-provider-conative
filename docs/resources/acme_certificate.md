# conative_acme_certificate (Resource)

A certificate in Azure Key Vault issued by an ACME certificate authority through DNS-01 challenges. Key Vault generates the private key (exportable, a new key for every version) and the signing request; the provider only passes the signing request to the authority and merges the issued certificate back. Neither the private key nor any password is ever in Terraform state. Renewal adds a new version to the same Key Vault certificate, so services that reference the versionless ID pick it up.

See the [ACME guide](../guides/acme-certificates-in-key-vault) for how issuance, renewal, failures and
permissions work.

## Example Usage

```terraform
# The Cloudflare API token is write-only: it is never stored in the plan or the state.
# Read it from an ephemeral resource.
ephemeral "azurerm_key_vault_secret" "cloudflare_token" {
  name         = "cloudflare-dns-token"
  key_vault_id = azurerm_key_vault.example.id
}

# One order for names in two DNS providers. Each name is answered by the block whose
# match_domains entry it matches.
resource "conative_acme_certificate" "example" {
  registration_id  = conative_acme_registration.letsencrypt.id
  key_vault_url    = azurerm_key_vault.example.vault_uri
  certificate_name = "example-com"

  common_name = "example.com"
  subject_alternative_names = [
    "*.example.com",
    "*.apps.example.net",
  ]

  key_type           = "RSA4096"
  min_days_remaining = 30
  revoke_on_destroy  = true

  cloudflare {
    zone          = "example.com"
    match_domains = ["example.com"]
    api_token     = ephemeral.azurerm_key_vault_secret.cloudflare_token.value
  }

  azure_dns {
    subscription_id = "00000000-0000-0000-0000-000000000000"
    resource_group  = "dns"
    zone_name       = "example.net"
    match_domains   = ["apps.example.net"]
  }
}
```

## Schema

### Required

- `certificate_name` (String) The Key Vault certificate name. The resource owns this certificate; creating it fails if the name already holds an issued certificate (import it instead). Changing it replaces the resource.
- `common_name` (String) The certificate's common name; always also a subject alternative name. Changing it issues a new version.
- `key_type` (String) `RSA2048`, `RSA3072`, `RSA4096`, `P256`, `P384`, `P521`. The certificate authority decides which it accepts (Let's Encrypt does not accept `P521`). Changing it issues a new version.
- `key_vault_url` (String) The vault URL, for example `https://example.vault.azure.net/`. Changing it to another vault replaces the resource; a different spelling of the same URL does not.
- `registration_id` (String) The `id` of a `conative_acme_registration`.
- `revoke_on_destroy` (Boolean) Whether destroying the resource revokes the certificate at the authority before deleting it from Key Vault. A certificate that was imported and not yet renewed by this resource is never revoked (it was issued elsewhere); destroy warns and deletes it.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `azure_dns` (Block List) An Azure DNS zone that answers challenges. At least one `azure_dns` or `cloudflare` block is required, and every name of the certificate must be covered by one of them. (see [below for nested schema](#nestedblock--azure_dns))
- `cloudflare` (Block List) A Cloudflare zone that answers challenges. (see [below for nested schema](#nestedblock--cloudflare))
- `min_days_remaining` (Number) Renew when the certificate expires within this many days. A plan then shows an in-place update that orders a new version.
- `subject_alternative_names` (Set of String) Further DNS names. Wildcards are written `*.example.com`. Do not repeat `common_name`. Changing them issues a new version.

### Read-Only

- `certificate_pem` (String) The current certificate (public), PEM.
- `id` (String) The versionless Key Vault certificate ID, `https://<vault>/certificates/<name>`.
- `issued_version` (String) The version this resource issued last, or after import the version that was current then. When `version` differs, the certificate changed outside Terraform and the next plan renews it.
- `not_after` (String) Expiry of the current certificate, RFC 3339.
- `secret_id` (String) The versionless Key Vault secret ID, `https://<vault>/secrets/<name>`, which services such as Azure Front Door and Azure Container Apps use to load the certificate.
- `thumbprint` (String) SHA-1 thumbprint of the current certificate, upper-case hexadecimal.
- `version` (String) The certificate's current version in Key Vault.

## Importing an existing certificate

Any Key Vault certificate can be imported, including one issued by another certificate authority, created
with another issuer, imported into Key Vault from a PFX file, or whose key is not exportable. Import only
reads the certificate's current version; it never reads the private key, the secret or the certificate
policy, and it changes nothing.

- From the current version, import sets `version` and `issued_version` (both that version),
  `certificate_pem`, `not_after`, `thumbprint`, `common_name` (the subject common name),
  `subject_alternative_names` (the certificate's DNS names in lower case, without the common name) and
  `key_type` (from the public key). `min_days_remaining` is set to `30`.
- Key Vault cannot report `registration_id`, `revoke_on_destroy` or the DNS blocks. The first plan after
  import therefore always shows one in-place update that only records them (and `min_days_remaining` if it
  is not `30`, and `key_vault_url` if it is written differently, for example with a trailing `/`). Applying
  it contacts neither the certificate authority nor Key Vault nor any DNS zone for a change. The plan after
  that shows no changes.
- If the certificate is within `min_days_remaining` days of expiry, or its names or key type differ from the
  configuration, the first plan instead shows an update that orders a new certificate.
- The issuer, policy, lifetime actions and key exportability of the imported certificate never cause an
  order by themselves. The first order (renewal or a change of names or key type) adds a new version to the
  same Key Vault certificate with a new key generated in Key Vault and replaces the certificate policy with
  this resource's (issuer `Unknown`, exportable key, the configured key type and names, no automatic
  actions). The versionless certificate and secret IDs stay the same, so services that use them pick up the
  new version. Until then, Key Vault keeps acting on the old policy: a version it adds on its own triggers a
  renewal at the next plan, and a pending request to another issuer makes the order fail until it is
  cancelled.
- Import fails, and nothing is stored, when the certificate has no issued version, has no subject common
  name, has a common name that is not one of its DNS names, has a subject alternative name that is not a DNS
  name (IP address, e-mail address, URI), has a name that is not a valid DNS name, or has a key other than
  RSA 2048/3072/4096 or EC P-256/P-384/P-521.
- A certificate imported and not yet renewed by this resource is not revoked on destroy, even with
  `revoke_on_destroy = true`; destroy warns and deletes it from Key Vault.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import by the versionless Key Vault certificate ID. This also adopts a certificate that
# was issued elsewhere or imported into Key Vault from a PFX file; see "Importing an
# existing certificate" on this page.
terraform import conative_acme_certificate.example https://example.vault.azure.net/certificates/example-com
```
